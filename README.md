# GigaChat Agents

Локальная pre-API версия Windows-приложения на Electron, React и TypeScript. Чаты, проекты, настройки, разрешения, Skills, Hooks и диктовка работают локально. Провайдер GigaChat API ещё не подключён: сообщение сохраняется в истории и не отправляется модели.

## Требования

- Node.js 22.x
- npm 10.x

## Команды

```powershell
npm install
npm start
npm test
npx tsc --noEmit
npm run package
npm run make
npx tsx scripts/seed-test-profile.ts
```

Для read-only проверки собственной включённой записи автозапуска в установленной Windows-версии используйте `node scripts/verify-login-item-readback.cjs`. Скрипт запускает Electron с отдельными путями в `.qa`, блокирует setter и записывает результат в `.qa/plan007-owner-upgrade-20261005/login-item-readback/result.json`; он не создаёт и не меняет записи автозапуска.

`npm start` запускает приложение для разработки. `npm run package` создаёт запускаемую сборку в `out/`, не устанавливая её в систему. На Windows `npm run make` создаёт Squirrel Setup.exe и `.nupkg` в `out/make/squirrel.windows/x64/`; сборка сама не запускает установщик и не подтверждает установку или автозапуск. Перед сборкой `scripts/prepare-squirrel-vendor.mjs` сверяет и загружает NuGet 7.9.0.83 с официального versioned URL по SHA-256 `992d70cac5b06c38efec91806caba64cdcc07e6d963a0959dbbbaf264d33b800` и помещает его вместе с неизменёнными инструментами `electron-winstaller` в игнорируемый `resources/native/`. Этот build-only каталог не попадает в ресурсы приложения. `seed-test-profile.ts` создаёт только в игнорируемой `.qa/profile` помеченный тестовый диалог с примером ответа и файлами Markdown/PDF. Для его просмотра запустите EXE с `--user-data-dir="<полный путь к app/.qa/profile>"`; обычный профиль остаётся пустым.

Отдельный x64 NSIS-кандидат можно собрать после `npm run package` командой `npx --no-install electron-builder --config electron-builder.yml --prepackaged "out/GigaChat Agents-win32-x64" --win nsis --x64 --publish never`. Он создаётся в `out/nsis/` и сам не запускает установку; `npm run make` пока остаётся Squirrel.

## Локальные данные

Настройки, чаты, проекты, черновики и глобальная инструкция `GIGACHAT.md` хранятся в каталоге Electron `app.getPath('userData')` — в Windows внутри `%APPDATA%\GigaChat Agents`. Каждый чат имеет устойчивый ID и свой каталог `chats/<uuid>/`: в `chat.json` находятся название, проект, состояние архива и закрепления, черновик, сообщения и перечень файлов; сами копии файлов находятся в `files/`. Старый `chats.json` версий 1–2 переносится один раз, сохраняется без изменений и копируется в `chats.json.bak`. Проектный `AGENTS.md` находится в корне выбранной рабочей папки и читается при подготовке каждого хода. Папки автоматически создаваемых проектов и папки проектов без рабочей папки размещаются в `Документы\GigaChat Agent\Projects\GigaChat Project N`; настройка «Дополнительная папка для открытия» на этот путь не влияет. При перепривязке существующий `AGENTS.md` в новой папке не перезаписывается; если прежняя папка недоступна, новая привязка сохраняется с предупреждением, а прежний файл остаётся на исходном месте. Внешний конфликт редактора сохраняет локальный черновик и внешнюю версию до явного выбора «Перечитать» или «Сохранить копию». Удаление проекта не удаляет его рабочую папку и файлы. Введённый вручную ключ хранится отдельно в зашифрованном `safeStorage` формате Windows DPAPI; приложение не использует и не проверяет его до отдельного API-этапа. DPAPI защищает данные от других учётных записей Windows, но не от программ того же пользователя.

До подключения API работают локальные чаты, сообщения пользователя, вложения, проекты, архив, выбор папки и программы открытия, инструкции, а также темы Изумрудная / Тёмная / Светлая / Тёплая и режим «Как в Windows». Изумрудная — тема новой установки; прежняя сохранённая «Тёмная» переносится в «Изумрудную» без изменения вида. Режим Windows использует нейтральную тёмную тему при тёмном оформлении системы. Темы, переключатели и инструкции сохраняются автоматически; при ошибке записи введённый текст остаётся в редакторе. Сообщение и очистка его черновика записываются вместе. Выбранный файл копируется в каталог чата; исходник не меняется, архив сохраняет копии, подтверждённое удаление чата убирает только копии. В области ввода проект выбирается через поиск и отдельное действие создания; разрешения и модель выбираются через меню приложения. Выбранная модель хранится в чате, модель по умолчанию — в настройках. Четыре модели перечислены заранее, но их доступность для конкретного ключа проверяется только на API-этапе. Настройки занимают всю рабочую область. На остальных экранах панель можно полностью скрыть, временно показать наведением на кнопку и закрепить нажатием. Окно запускается размером до 960×720 с масштабом содержимого 80%; Ctrl+`+` / Ctrl+`−` меняют масштаб, Ctrl+`0` возвращает 100%. При узкой области навигация открывается поверх основного экрана. Нативные кнопки окна сохраняют размер.

Импорт ограничен 25 МиБ на файл; `GIGACHAT.md` и проектные `AGENTS.md` ограничены 64 КиБ и проверяются до чтения. Пути локального хранилища строятся из валидированных ID и имён файлов, а symlink/junction внутри него отклоняются, в том числе если они появились после запуска.

Локальный инструмент агента «открыть» показывает папку в Проводнике или открывает проверенный UTF-8 текстовый файл размером до 1 МиБ в Блокноте Windows, не передавая документ обработчику файловых ассоциаций. Исполняемые файлы, скрипты, ярлыки, URL, неизвестные типы и двоичные файлы этим инструментом не запускаются.

Переключатель вверху боковой панели показывает GigaChat API или GigaChat Web только в текущем сеансе. Подключение Web появится позже; выбор пока не меняет возможности приложения. Значок окна и сборки создан из круглой части `src/assets/gigachat-logo.png` без внешнего квадратного свечения и без изменения формы логотипа.

Меню действий чатов и проектов открываются на непрозрачной поверхности поверх основной области. Список для «Переместить в проект» открывается сбоку после 0,5 секунды наведения или сразу по нажатию; если проектов нет, показывает «Нету проектов». Создание, переименование и удаление используют диалоги внутри окна. Успешные уведомления исчезают через две секунды; ошибки закрываются вручную. Настройки открываются шестерёнкой у локального профиля, возврат — кнопкой «Назад»; верхние кнопки справки и настроек удалены. Копирование разрешено в сообщениях, полях ввода, редакторах и путях.

## Состояние перед API

Первый запуск открывает встроенный Chromium экран GigaChat Studio и предлагает продолжить локально. Встроенная страница использует отдельную временную Electron session без preload и доступа к IPC приложения; приложение не считывает поля, cookies или ключ со страницы. Реальный ключ сейчас не вводить: поле предназначено для будущего подключения, текущая проверка API не выполняется. Проверены публичные экраны входа и регистрации без учётной записи; авторизация реальными данными не проверялась.

Профили разрешений сохраняются для следующего хода. В обычной сборке провайдер отсутствует, поэтому обычная отправка только сохраняет пользовательское сообщение локально и не создаёт фиктивный ответ или ход. Доступные локальные действия проверяются на стороне main перед запуском. В режиме «Спросить» действия в выбранном проекте выполняются в проверенной границе; режим «Подтверждать за меня» пока не имеет автопроверяющего и передаёт спорные действия пользователю. «Полный доступ» разрешает только существующие инструменты и не открывает всю машину или сеть. «Пользовательский» использует `%APPDATA%\GigaChat Agents\config.toml`: правила `allow`, `ask`, `deny` для списка, поиска, чтения, записи, открытия и ограниченного PowerShell. При `ask` появляется диалог с действием и целью; отмена и истечение 60 секунд отклоняют запрос. Файл можно править в настройках или снаружи; неверный TOML не заменяет последнюю рабочую политику. Дополнительные каталоги задаются явными абсолютными путями и проходят ту же проверку. Если локальный инструмент отсутствует, профиль не включает его.

Main-owned `LocalTools` реализует список, поиск, чтение, запись, открытие и PowerShell. PowerShell запускается в AppContainer с Job Object; проверенные packaged QA сценарии покрывают проектную папку, обычный соседний sentinel, loopback, лимиты, отмену и восстановление ACL. Произвольный script IPC renderer отсутствует. Файловые операции используют явный проверенный корень проекта и AppContainer helper; замена существующего обычного файла разрешена только при совпадении owner/group/DACL/mandatory integrity label до операции. Для специальной метки, несовпадающих или недоступных метаданных запись завершается отказом. Другие SACL ACE этим доказательством не покрыты. В AppContainer `Get-Location` может быть `C:\`; `$env:GIGACHAT_PROJECT_ROOT` — только подсказка, относительные пути PowerShell не привязаны к проекту. Прямые packaged проверки helper и `LocalTools` выполнены на synthetic QA-файлах; файловый tool пока не вызывается из renderer UI, поскольку GigaChat provider ещё отсутствует.

Каталог `resources/voice` формируется при сборке скриптом `scripts/prepare-voice-resources.mjs`: pinned Windows `gigastt` 2.21.0, GigaAM v3 `e2e_rnnt` и Silero VAD скачиваются по версии и проверяются по SHA-256; модель не скачивается при запуске установленного приложения. Диктовка распознаёт аудио локально, добавляет текст в редактируемый composer и ничего не отправляет. Изолированный packaged fake-microphone прогон подтвердил ручную остановку после 5 минут (300 482 мс) и автоматическую остановку после 10 минут (600 648 мс), редактируемый черновик, отсутствие отправленных сообщений, очистку временной аудиозаписи и повторное использование локальных ресурсов после перезапуска. Это проверяет длительность и жизненный цикл на синтетическом аудио, но не качество распознавания естественной речи или смешанного RU/EN текста. Временная запись хранится в app-owned `userData/voice-temp`; штатное завершение очищает её, а после аварийного завершения файл может оставаться до подтверждённого удаления локальных данных. Отмена захвата подтверждается после очистки принадлежащих ему ресурсов; если очистку нельзя подтвердить, повторный запуск блокируется до успешной попытки восстановления. Ресурсы работают на CPU; этот Windows release не предоставляет GPU backend.

Каталог Skills поддерживает app-owned Global и Project `SKILL.md` с короткими полями `name` и `description`; выбор `$` сохраняется для следующего хода. Scripts/assets Skills не выполняются. Hooks показывают найденные записи, но произвольное исполнение выключено. Настройки содержат локальные счётчики чатов/проектов/UTC-дней активности; доступность выбранной модели, API-токены, баланс и тепловая карта остаются неизвестными до реальных измерений. Windows notifications имеют отдельные категории; ошибки локальных операций могут уведомляться, а старт очереди и ответ модели ждут провайдера.

Удаление всех данных приложения требует отдельного подтверждения main process. После подтверждения упакованный helper закрывает приложение и удаляет только проверенный `%APPDATA%\GigaChat Agents`; packaged QA на изолированном профиле подтвердил исчезновение каталога и сохранность внешней рабочей папки, исходного вложения и sentinel за junction. Внешние проекты и исходные файлы не удаляются.

## Handoff для API-этапа

Main-side контракт провайдера — `GigaChatProvider.stream(request, signal): AsyncIterable<ProviderEvent>`. `ProviderTurnRequest` содержит `system: InstructionLayer[]` (`source`, `label`, optional `scope`, `text`), историю `messages` (`id`, `role`, `text`, `createdAt`), `modelId` и `permissionProfile`. Без явно выбранной модели запрос провайдеру не запускается. Провайдер сообщает `activity` (событие и optional tool), `text-delta`, `completed` (optional `responseId`) или `error` (`code`, `retryable`). Существующая очередь ограничивает активный ход одним; принятый ход сохраняет значения запроса на момент отправки, а отмена ждёт ограниченного завершения принадлежащих ему операций и очистки перед следующим ходом. Инструменты и `AbortSignal` остаются на доверенной main стороне. Тестовый provider доступен только тестам. При подключении ключа список доступных моделей нужно получить через `GET /v1/models`, не подменяя выбранную недоступную модель другой.

По текущей официальной документации [базовый адрес API](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api) — `https://api.giga.chat`; endpoint получения токена отдельно указан как `https://ngw.devices.sberbank.ru:9443/api/v2/oauth`, с `RqUID` формата UUIDv4 и `scope=GIGACHAT_API_PERS`; access token действует 30 минут ([документация токена](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/post-token)). Без ключа проверен только TLS handshake через per-request app-level CA с включённой проверкой сертификата; получен HTTP 403, не проверка авторизации. API-вызов, OAuth/refresh, модели и лимиты, streaming/function calling и качество естественной речи остаются открытыми. Не применять устаревший SDK default, не отключать TLS и не менять системное хранилище сертификатов.

Packaged visual QA на изолированном профиле проверил пять тем на представительных экранах Appearance/Permissions при 960×720 и native `PrintWindow` onboarding со встроенной страницей Studio. Отдельный Stage8 проход снял главный экран, синтетический длинный чат с Markdown/PDF, проект, архив, профиль и все 9 разделов настроек в тёмной теме; исправленные светлые снимки подтверждают темы «Общие» и «Проекты и файлы». Settings/Files также проверен при клиентских размерах 560×480 и 1424×892 без горизонтального переполнения. В этой Windows-среде System разрешился в тёмную тему. 2026-09-28 пользователь физически подтвердил в изолированном packaged окне сочетания Ctrl+0, Ctrl+Plus и Ctrl+Minus без ошибок. UI очереди/отмены/ошибки хода в packaged приложении остаётся непроверенным без провайдера; доставку Windows-уведомления не проверяли без реального локального события. Доказательства Stage8 находятся в `.qa/pre-api/runtime-status-778e17a6-3612-440d-ab54-7158069bcde7/`; это автоматизированное покрытие, не субъективная приёмка пользователя.

Windows Squirrel `make` завершился успешно. Проверены `RELEASES`, SHA-1 и размер `.nupkg`, состав пакета и значок Setup.exe. ICO в пакете совпадает с исходным ICO по SHA-256; associated icon, извлечённый из Setup.exe, визуально соответствует логотипу. Установщик находится в `out/make/squirrel.windows/x64/GigaChat Agents-1.0.0 Setup.exe` и не запускался.

## Проверка реализации и ограничения — 2026-10-04

Текущая проверка прошла: 159/159 тестов, TypeScript и ESLint; packaged renderer harness — 27/27. Свежие `npm run package` и `npm run make` завершились успешно. Изолированная Windows-проверка охватила восстановление и перепривязку проекта, конфликт редактора инструкций, закрытие/возврат при ошибках сохранения, восстановление браузерных вкладок и безопасное открытие текстового файла. Обнаружение VS Code пассивное, повторный запуск использует уже открытый экземпляр; выбор программы запуска выполняется только по явному действию пользователя. При закрытии принятые изменения ожидают завершения: ошибка проекта или настроек сохраняет окно для восстановления, а ошибка только метаданных браузера предлагает повторить сохранение, вернуться или отдельно отказаться от этих метаданных.

Автозапуск доступен только при подтверждённом стабильном файле запуска установленной версии; в переносном запуске настройка показана как недоступная. Реальную установку и обновление установленной версии не проверяли. Полный `npm audit` остаётся заблокирован пятью high findings в цепочке разработки/сборки через `braces` (GHSA-vfj7-8cjw-p6xm); на дату проверки совместимого исправленного upstream-релиза не найдено. Production dependency audit завершился без findings. Никакие audit findings не подавлялись.

Проверки выполнялись на синтетическом профиле: реальный API, ключ и микрофон не использовались. Проверки ссылок, безопасности и восстановления подтверждают перечисленные сценарии, но не гарантируют защиту от произвольного конкурентного изменения файловой системы другим процессом. Наблюдение за запуском VS Code шло с интервалом 250 мс и не исключает процесс короче этого интервала. Физическую установку/upgrade Squirrel нельзя считать проверенной по запуску Setup.exe из сборки.
