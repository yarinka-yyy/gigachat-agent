# GigaChat Agents

Windows-приложение на Electron, React и TypeScript с локальными чатами, проектами, настройками, разрешениями, Skills, Hooks, диктовкой и подключаемым GigaChat API. Сообщение отправляется модели только после успешного Connect и проверки выбранной модели; без доступного подключения оно остаётся локальным.

## Требования

- Node.js 22.x
- npm 10.x

## Команды

```powershell
npm install
npm start
npm test
npx tsc --noEmit
npm run package
npm run make
npx tsx scripts/seed-test-profile.ts
```

Для read-only проверки собственной включённой записи автозапуска в установленной Windows-версии используйте `node scripts/verify-login-item-readback.cjs`. Скрипт запускает Electron с отдельными путями в `.qa`, блокирует setter и записывает результат в `.qa/plan007-owner-upgrade-20261005/login-item-readback/result.json`; он не создаёт и не меняет записи автозапуска.

`npm start` запускает приложение для разработки. `npm run package` создаёт запускаемую сборку в `out/`, не устанавливая её в систему. На Windows `npm run make` создаёт Squirrel Setup.exe и `.nupkg` в `out/make/squirrel.windows/x64/`; сборка сама не запускает установщик и не подтверждает установку или автозапуск. Перед сборкой `scripts/prepare-squirrel-vendor.mjs` сверяет и загружает NuGet 7.9.0.83 с официального versioned URL по SHA-256 `992d70cac5b06c38efec91806caba64cdcc07e6d963a0959dbbbaf264d33b800` и помещает его вместе с неизменёнными инструментами `electron-winstaller` в игнорируемый `resources/native/`. Этот build-only каталог не попадает в ресурсы приложения. `seed-test-profile.ts` создаёт только в игнорируемой `.qa/profile` помеченный тестовый диалог с примером ответа и файлами Markdown/PDF. Для его просмотра запустите EXE с `--user-data-dir="<полный путь к app/.qa/profile>"`; обычный профиль остаётся пустым.

Отдельный x64 NSIS-кандидат можно собрать после `npm run package` командой `npx --no-install electron-builder --config electron-builder.yml --prepackaged "out/GigaChat Agents-win32-x64" --win nsis --x64 --publish never`. Он создаётся в `out/nsis/` и сам не запускает установку; `npm run make` пока остаётся Squirrel.

## Локальные данные

Настройки, чаты, проекты, черновики и глобальная инструкция `GIGACHAT.md` хранятся в каталоге Electron `app.getPath('userData')` — в Windows внутри `%APPDATA%\GigaChat Agents`. Каждый чат имеет устойчивый ID и свой каталог `chats/<uuid>/`: в `chat.json` находятся название, проект, состояние архива и закрепления, черновик, сообщения и перечень файлов; сами копии файлов находятся в `files/`. Старый `chats.json` версий 1–2 переносится один раз, сохраняется без изменений и копируется в `chats.json.bak`. Проектный `AGENTS.md` находится в корне выбранной рабочей папки и читается при подготовке каждого хода. Папки автоматически создаваемых проектов и папки проектов без рабочей папки размещаются в `Документы\GigaChat Agent\Projects\GigaChat Project N`; настройка «Дополнительная папка для открытия» на этот путь не влияет. При перепривязке существующий `AGENTS.md` в новой папке не перезаписывается; если прежняя папка недоступна, новая привязка сохраняется с предупреждением, а прежний файл остаётся на исходном месте. Внешний конфликт редактора сохраняет локальный черновик и внешнюю версию до явного выбора «Перечитать» или «Сохранить копию». Удаление проекта не удаляет его рабочую папку и файлы. Введённый вручную ключ хранится отдельно в зашифрованном `safeStorage` формате Windows DPAPI и используется только OAuth-подключением после действия «Подключить». Access token хранится в памяти процесса; сохранённый ключ и access token не возвращаются в renderer. DPAPI защищает секрет в покое, но не от программ, работающих от имени того же пользователя.

Локально работают чаты, сообщения, вложения, проекты, архив, выбор папки и программы открытия, инструкции, темы Изумрудная / Тёмная / Светлая / Тёплая и режим «Как в Windows». Изумрудная — тема новой установки; прежняя сохранённая «Тёмная» переносится в «Изумрудную» без изменения вида. Режим Windows использует нейтральную тёмную тему при тёмном оформлении системы. Темы, переключатели и инструкции сохраняются автоматически; при ошибке записи введённый текст остаётся в редакторе. Сообщение и очистка его черновика записываются вместе. Выбранный файл копируется в каталог чата; исходник не меняется, архив сохраняет копии, подтверждённое удаление чата убирает только копии. В области ввода проект выбирается через поиск и отдельное действие создания; разрешения и модель выбираются через меню приложения. Выбранная модель хранится в чате, модель по умолчанию — в настройках. Список доступных моделей загружается из API после Connect; недоступная сохранённая модель не подменяется автоматически. Настройки занимают всю рабочую область. На остальных экранах панель можно полностью скрыть, временно показать наведением на кнопку и закрепить нажатием. Окно запускается размером до 960×720 с масштабом содержимого 80%; Ctrl+`+` / Ctrl+`−` меняют масштаб, Ctrl+`0` возвращает 100%. При узкой области навигация открывается поверх основного экрана. Нативные кнопки окна сохраняют размер.

Импорт ограничен 25 МиБ на файл; `GIGACHAT.md` и проектные `AGENTS.md` ограничены 64 КиБ и проверяются до чтения. Пути локального хранилища строятся из валидированных ID и имён файлов, а symlink/junction внутри него отклоняются, в том числе если они появились после запуска.

Локальный инструмент агента «открыть» показывает папку в Проводнике или открывает проверенный UTF-8 текстовый файл размером до 1 МиБ в Блокноте Windows, не передавая документ обработчику файловых ассоциаций. Исполняемые файлы, скрипты, ярлыки, URL, неизвестные типы и двоичные файлы этим инструментом не запускаются.

Переключатель вверху боковой панели показывает GigaChat API или GigaChat Web только в текущем сеансе. Подключение Web появится позже; выбор пока не меняет возможности приложения. Значок окна и сборки создан из круглой части `src/assets/gigachat-logo.png` без внешнего квадратного свечения и без изменения формы логотипа.

Меню действий чатов и проектов открываются на непрозрачной поверхности поверх основной области. Список для «Переместить в проект» открывается сбоку после 0,5 секунды наведения или сразу по нажатию; если проектов нет, показывает «Нету проектов». Создание, переименование и удаление используют диалоги внутри окна. Успешные уведомления исчезают через две секунды; ошибки закрываются вручную. Настройки открываются шестерёнкой у локального профиля, возврат — кнопкой «Назад»; верхние кнопки справки и настроек удалены. Копирование разрешено в сообщениях, полях ввода, редакторах и путях.

## Подключение и локальные действия

Первый запуск открывает встроенный Chromium экран GigaChat Studio и предлагает продолжить локально. Встроенная страница использует отдельную временную Electron session без preload и доступа к IPC приложения; приложение не считывает поля, cookies или ключ со страницы. Для API-подключения пользователь вручную сохраняет ключ и отдельно запускает Connect: приложение выполняет OAuth и обновляет список моделей. Настоящий аккаунт и ключ в Plan010 fixtures не использовались.

Профили разрешений сохраняются для следующего хода, а доступные действия проверяются в main. «Спросить» и «Пользовательский» применяют ограниченную политику к локальным инструментам; запрос за её пределы показывает действие и цель для подтверждения. «Подтверждать за меня» не имеет отдельного reviewer и использует явный запрос пользователю. «Полный доступ» выполняет существующие локальные инструменты в пределах прав текущего Windows-пользователя, включая доступ вне папки проекта и сеть; это не sandbox и не повышение прав. Пользовательский профиль хранится в `%APPDATA%\GigaChat Agents\config.toml` и задаёт правила `allow`, `ask`, `deny` для списка, поиска, чтения, записи, открытия и ограниченного PowerShell. Отмена и истечение 60 секунд отклоняют запрос. Неверный TOML не заменяет последнюю рабочую политику. Дополнительные каталоги задаются явными абсолютными путями и проверяются перед действием. Если локальный инструмент отсутствует, профиль не включает его.

Main-owned `LocalTools` реализует список, поиск, чтение, запись, открытие и PowerShell; renderer не получает произвольный script IPC. Ограниченные профили используют проверенную project boundary и AppContainer helper там, где это требуется. Full использует отдельный доверенный Windows process, Job Object, bounded environment и отмену; его проектная папка и команда повторно проверяются перед запуском. Для записи обычного существующего файла проверяется owner/group/DACL/mandatory integrity label; специальные, несовпадающие или недоступные метаданные приводят к отказу. Native fixtures покрыли внешнюю временную папку, localhost, отмену процесса и восстановление. При отмене Full нет обещания изоляции от других программ того же Windows-пользователя.

Каталог `resources/voice` формируется при сборке скриптом `scripts/prepare-voice-resources.mjs`: pinned Windows `gigastt` 2.21.0, GigaAM v3 `e2e_rnnt` и Silero VAD скачиваются по версии и проверяются по SHA-256; модель не скачивается при запуске установленного приложения. Диктовка распознаёт аудио локально, добавляет текст в редактируемый composer и ничего не отправляет. Изолированный packaged fake-microphone прогон подтвердил ручную остановку после 5 минут (300 482 мс) и автоматическую остановку после 10 минут (600 648 мс), редактируемый черновик, отсутствие отправленных сообщений, очистку временной аудиозаписи и повторное использование локальных ресурсов после перезапуска. Это проверяет длительность и жизненный цикл на синтетическом аудио, но не качество распознавания естественной речи или смешанного RU/EN текста. Временная запись хранится в app-owned `userData/voice-temp`; штатное завершение очищает её, а после аварийного завершения файл может оставаться до подтверждённого удаления локальных данных. Отмена захвата подтверждается после очистки принадлежащих ему ресурсов; если очистку нельзя подтвердить, повторный запуск блокируется до успешной попытки восстановления. Ресурсы работают на CPU; этот Windows release не предоставляет GPU backend.

Каталог Skills поддерживает app-owned Global и Project `SKILL.md` с короткими полями `name` и `description`; выбор `$` сохраняется для следующего хода, scripts/assets не исполняются. Командные Hooks можно просмотреть, доверие привязано к SHA-256 проверенного содержимого, а включение выполняется отдельно; запускаются только доверенные доступные обработчики поддерживаемых событий. API usage сохраняется по валидированным receipts. Receipt показывает учтённый API расход токенов, но сам по себе не подтверждает баланс, лимиты или точный размер следующего контекста; без отдельно подтверждённых данных они остаются неизвестными. Windows notifications имеют отдельные категории; успешный ответ уведомляется после сохранения в истории.

Удаление всех данных приложения требует отдельного подтверждения main process. После подтверждения упакованный helper закрывает приложение и удаляет только проверенный `%APPDATA%\GigaChat Agents`; packaged QA на изолированном профиле подтвердил исчезновение каталога и сохранность внешней рабочей папки, исходного вложения и sentinel за junction. Внешние проекты и исходные файлы не удаляются.

## Состояние интеграции GigaChat API

Провайдер `GigaChatProvider.stream` работает в main process: после Connect он получает OAuth token, загружает реестр моделей и обрабатывает GigaChat SSE, включая текстовые delta, завершение, usage и последовательный вызов существующих локальных инструментов. Сохранённая недоступная модель не заменяется другой. Очередь сериализует ходы и ожидает отмену, сохранение и остановку принадлежащих ходу операций. Production не содержит тестового провайдера или фиктивной авторизации.

Документация указывает [базовый адрес API](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api) `https://api.giga.chat` и [OAuth endpoint](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/post-token) `https://ngw.devices.sberbank.ru:9443/api/v2/oauth`. Fixtures проверяют OAuth, TLS-политику, model discovery, SSE/function protocol и usage; они не подтверждают entitlements, доступность или качество реального аккаунта. Не отключать TLS и не менять системное хранилище сертификатов.

Packaged visual QA на изолированном профиле проверил пять тем на представительных экранах Appearance/Permissions при 960×720 и native `PrintWindow` onboarding со встроенной страницей Studio. Отдельный Stage8 проход снял главный экран, синтетический длинный чат с Markdown/PDF, проект, архив, профиль и все 9 разделов настроек в тёмной теме; исправленные светлые снимки подтверждают темы «Общие» и «Проекты и файлы». Settings/Files также проверен при клиентских размерах 560×480 и 1424×892 без горизонтального переполнения. В этой Windows-среде System разрешился в тёмную тему. 2026-09-28 пользователь физически подтвердил в изолированном packaged окне сочетания Ctrl+0, Ctrl+Plus и Ctrl+Minus без ошибок. Plan010 добавил проверки очереди, Stop, draft, retry, подтверждения локального действия, Hook, usage и Unknown в harness с актуальным React renderer и синтетическим preload; его статусы и tool events введены fixture и не являются доказательством реального ответа провайдера. Доставка Windows-уведомления и субъективная приёмка интерфейса остаются отдельными проверками. Доказательства Stage8 находятся в `.qa/pre-api/runtime-status-778e17a6-3612-440d-ab54-7158069bcde7/`.

Windows Squirrel `make` завершился успешно. Проверены `RELEASES`, SHA-1 и размер `.nupkg`, состав пакета и значок Setup.exe. ICO в пакете совпадает с исходным ICO по SHA-256; associated icon, извлечённый из Setup.exe, визуально соответствует логотипу. Установщик находится в `out/make/squirrel.windows/x64/GigaChat Agents-1.0.0 Setup.exe` и не запускался.

## Проверка Plan009 — 2026-10-06

Вкладки браузера находятся в строке заголовка чата. Переключение между чатом и браузером сохраняет страницу, её историю и черновик чата.
